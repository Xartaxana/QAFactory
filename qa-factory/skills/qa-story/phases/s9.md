# S9 — Closure and retro

`stages.json` ids used: `S9` (`role: qa-retro-analyst`, `requires: ["S8"]`,
`gate_before: "B"`, inputs `pipeline.json`, `project:records/journal.jsonl`,
`project:state/cost/`, outputs `retro.md`, `project:obligations.md`,
`project:factory-backlog.md`, `required_outputs: ["retro.md"]` — the obligations and backlog
rows exist only when this run produced any, so they cannot be required outputs).
`required_outputs` is checked at a role's handover, so it binds the dispatched `full` retro;
the `numbers` mode writes the same `retro.md` by code and `skip` writes none.

The story is delivered: gate B is decided and every order it gave (the bugs filed, the MR opened or called off) is executed or cancelled. What is left is turning this run into something the next run does
not have to learn again — and one question to the human.

## Card

Input: S8 `done`, gate B decided and every order it gave executed or cancelled (`controller.py --operation next` answers `closed`; while it answers `execute_gate_b` S9 does not start). `pipeline.json.retro_mode` missing, unreadable or anything but `numbers`/`skip` = `full`: the retro runs. `numbers` and `skip` are never written from 0.10.9 on (the retro is always full; `stage_done` refuses them); a story an older version recorded with one of them still runs that mode.

python "${CLAUDE_PLUGIN_ROOT}/scripts/log_append.py" --event escalated --agent qa-story --task <TICKET> --reason "retro feedback: <the answer, verbatim, or 'declined'>"

Halts (the table "Halts of this phase"): `cannot compute retro` -> name the missing file; a `stage_guard` denial -> S8 is not `done`, go back to it; `retro.md` missing after `done` -> one re-dispatch, then halt; `stage_done` refuses on a running tail -> `controller.py --task-root <T> --operation recover`; a role that set `archived` -> clear the flag.

S9 is the last stage: there is no next card.

## 0. The retro always runs in full

Read `pipeline.json.retro_mode`. Missing, unreadable or `full` = **the retro runs.** A story
onboarded before this key existed gets the whole retro. `numbers` and `skip` occur only in a
story an older version recorded; they run as recorded. They are never written now, never offered
as a menu, and silence is never read as one of them.

| `retro_mode` | What runs | Why |
|---|---|---|
| `full` (default, and the silent one) | `retro_numbers.py`, then one dispatch of `qa-retro-analyst` over its output | Code does the arithmetic; the analyst does the part no table can do — the traps, the fold, the person's answer. |
| `numbers` | `retro_numbers.py --write-retro`, then `estimate_record.py`. **No dispatch, and nobody writes prose.** | An older version recorded the person's word for it; never written now. |
| `skip` | Nothing. Record the skip with their words. | An older version recorded the person's word for it; never written now. |

The retro starts only once `controller.py --operation next` answers `closed`: while gate B has an order not yet executed or cancelled,
`next` answers `execute_gate_b` (`phases/s8.md`, section 4) and the retro waits for it. A closed story whose work
never started asks first: `next` answers `closed` with `held`, and
the question is `run again` / `leave` / `stop` (a person's word, never the factory's; person-owned: risk). The
retro runs after the answer, and needs no word of its own.

The numbers are computed first in every mode, so no model ever does this arithmetic:

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/retro_numbers.py" --task <TICKET> \
  --output <TASK_ROOT>/work/retro-numbers.md --json-output <TASK_ROOT>/work/retro-numbers.json
```

Two of those numbers are findings about the factory, not costs the person owes: an
orchestrator share over `retro.orchestrator_share_max` (default 0.35), and a stage that
finished before it started. Both are printed with their stages and stamps; neither is a
question, and neither goes to the person as work.

**`numbers`** — you write nothing. Two calls, in this order, then section 2b, then section 3:

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/retro_numbers.py" --task <TICKET> --write-retro \
  --feedback "<their answer from section 1, verbatim, or leave empty>"
python "${CLAUDE_PLUGIN_ROOT}/scripts/estimate_record.py" --task <TICKET> \
  --facts <TASK_ROOT>/work/estimate-facts.json
```

The first renders `retro.md` from the numbers and the gate answers and writes the facts
file the second needs — the estimate record binds `retro.md`'s bytes, so nothing edits that
file afterwards. Without the second call the next `qa-doctor` reports audit A15 red on a
story that did nothing wrong. No knowledge fold, no strategy edit, no ledger row.

**`skip`** — one call, then section 2b, then section 3 with `--status skipped`:

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/log_append.py" --event escalated --agent qa-story \
  --task <TICKET> --reason "retro skipped by the person: <their words, verbatim>"
```

**`full`** — sections 1 and 2 below, then 2b.

## 1. The one optional question — fixed text

Ask it once, exactly as written, **before** the dispatch (and before `--write-retro` in the
`numbers` mode): the answer travels into the retro, and a question asked after the role has
already written its file has nowhere to land.

> One question for the retro: what did you dislike in this session, what should change?
> (optional — reply 'skip')

That is the whole message. No preamble, no list of what you think went wrong, no second
question. `skip`, silence or anything that is not an answer is recorded as declined, not
paraphrased into an opinion of your own.

Record it verbatim:

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/log_append.py" --event escalated --agent qa-story \
  --task <TICKET> --reason "retro feedback: <the answer, verbatim, or 'declined'>"
```

## 2. Dispatch — the default path (`retro_mode: full`)

Three commands (`references/judge.md`); `start` prints the `Agent` call below filled in:

python "${CLAUDE_PLUGIN_ROOT}/scripts/story_step.py" bind  --task <TICKET> --dispatch-id S9-qa-retro-analyst-1 --agent-id <id>   # on Claude the plugin's hook binds it; by hand only on Codex or when `where` says unbound

`finish` prints the judge's whole bill for the story — questions, share decided, money, and
how many blocks it passed — which is the line the retro's cost section quotes. With a judge
configured the analyst is told to settle a trap's owning document with `judge_results.py
--trap "<the paragraph>"` rather than write it into two of them (audit A21).

```

```

The analyst writes the prose over those numbers: the knowledge fold (owner answers from both
gates into `strategy/faq.md`, terms into the glossary, stand and data quirks into
`project-profile.md`, recurring traps into whichever strategy document owns that kind of
fact — code and run traps to `framework-rules.md`, planning traps to `test-strategy.md`,
never both, since audit A21 fails a section that exists in both — or, when the exact owning
file has no editable grant, as proposals appended to `test-report.md`),
the `obligations.md` rows this run leaves behind (read by S0 of the next story, selected by
trigger or by area — the only carrier between stories), the `estimation-ledger.jsonl` line,
the `factory-backlog.md` entries including the human's feedback row, and the dashboard
rebuild. **Nothing is archived here**: hiding a story from the dashboard and the doctor is
the human's word to `qa-doctor`, never a role's conclusion.

You do not write, fold or archive anything yourself. If the dashboard was not rebuilt, one
call closes it:

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/factory_dashboard.py"
```

## 2b. The report is rebuilt last — after gate B and after the retro

Before the rebuild, and never before the retro has run or been skipped, the stand's config is given back, so that the
report carries what was done to it: `python "${CLAUDE_PLUGIN_ROOT}/scripts/story_step.py" config-restore --task <TICKET>`
prints one JSON line; if it has a `line`, tell the person that line as it stands (what was reverted, what was kept, where the
copy of the file before the revert is); no `line` means nothing to say. The rebuild reads that line from the story's copy.

The report learns what the gate decided, and keeps asking for a word the person already gave
only if this step is skipped (on TP1-15045 it read "bugs await your word at gate B" a day
after the answer "into a file and into the chat"). Once the retro has run, or been skipped,
`numbers` included — never before it — the driver, or the conductor by hand on the skill road,
runs `report_facts.py --task <TICKET> --write`:

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/report_facts.py" --task <TICKET> --write
```

It applies gate B's pruning of "Left with you" (the items the person's words answered, and the
items that are only the factory's own bookkeeping), renders `## Decided at gate B` — the
person's words verbatim, where the bugs went, what went outward or "not recorded" — refreshes
the other blocks, and keeps everything outside the blocks: the prose of the scribe and the
retro analyst's proposals appended to `test-report.md` (section 2) sit outside the blocks and
survive the rebuild. Whenever it replaces a block, removes an item or converts a report, it
saves the previous bytes under `state/report-history/` and prints the file's name. A story
started before this change has a report with no markers: the first `--write` converts it, its
old bytes saved under `state/report-history/`, nothing deleted. When the rebuild changes the
verdict sentence after gate B, the block prints the old and the new text.

What `--write` prints: one line per change it made (a block replaced or removed, a report
converted, an item taken out of "Left with you", the name of the history file), then
`test-report.md: code-owned blocks refreshed (...)`; or, when it cannot run, one line saying what
is wrong and the door. It does not read the scribe's prose: an item with no `How:` is checked by
the S8 hook, not here. A line about a damaged marker, a report that is not there or one on the
older section list is the factory's own, never a question for the person: the door is the
scribe's rework, `story_step.py start --task <TICKET> --stage S8 --role qa-doc-scribe`. Nothing
edits the blocks by hand: the next `--write` would overwrite them.

The findings register (`work/exploratory-findings.jsonl`) is picked up by the same rebuild: while it holds a line, the report
carries the block `## Exploratory findings and unresolved questions` (none of it is a product bug, none is filed, none counts
as proven), and when the register holds no line the block is removed with its previous bytes saved. A finding made after S8
is recorded with `python "${CLAUDE_PLUGIN_ROOT}/scripts/exploratory_findings.py" add --task-root <story folder> ...`, then
`--write` is run again. The "Left with you" prose is never hand-edited to carry or withdraw a finding: a finding is
corrected or withdrawn in the register (`correct`, `withdraw`), and the report follows.

## 3. Exit

`stage_done.py --task <TICKET> --stage S9 --status done --digest "<digest>"` — state and
journal together; add `--role qa-retro-analyst` only when a dispatch actually ran (`full`).
For `skip`: `--status skipped --digest "retro skipped: <their words>"`.
Every stage should now read `done` or, for S9, `skipped` with the person's words next to it.

## 4. Post-retro delivery bookkeeping

After S9 is recorded complete, rebuild the exact compact allowlist with `delivery_manifest.py`. If the existing Gate B decision authorized updating the named MR/branch with QA records, add only the newly listed/changed exact paths (`retro.md`, final report/state and compact records), create the authorized update, and record its receipt. Do not open a new MR, broaden paths, or infer authorization. When Gate B did not authorize this target/scope, persist a pending delivery action naming the exact paths and target; the retro remains complete and visible locally. Evidence (raw runs and the exported copies under `evidence/`) remains excluded.

## 5. The final summary — at most 10 lines

The last thing the human sees. Nothing else after it:

```
<TICKET> — delivered.
Verified: <n> plan rows green, <n> tests, environment <env>, grounding <source>.
Open: <the ledger rows that are not passed_green, one line, with their gate B decisions>.
Bugs filed: <BUG ids, or none>. MR: <url, or 'not opened — <reason>'>.
Regression, yours to run when you want it: <the commands from test-report.md, or 'none needed — <why>'>.
Documents: qa-factory/artifacts/<TICKET>/test-report.md · retro.md
Next: <the one action — run the regression / answer the open questions / verify a bug fix>.
```

No retelling of the pipeline, no list of stages, no restatement of the ledger — it was in
the gate B message and it is on disk. Ten lines is a cap, not a target.

## Halts of this phase

| Digest | Action |
|---|---|
| `cannot compute retro — missing <file>` | Name the missing file. `retro_numbers.py` reports what it could not read instead of guessing; what it did compute still goes into `retro.md`. |
| A `stage_guard` denial on the S9 dispatch | Order (rule 1): S8 is not `done`. Go back to `s8.md` and finish it. |
| `retro.md` missing after `done` | Not done. One re-dispatch, then halt. |
| `stage_done` refuses S9 `done`: `<stage> is still running` | A closed story may not keep a running tail (it is what made 2534 the "second running story" for 2556). Run `controller.py --task-root <T> --operation recover`, then record S9 again; the person's word passes it (`waiver.py --stage S9 --block "still running"`). |
| The digest claims `archived` was set | A role must not set it. Clear the flag, and tell the human that archiving is offered by `qa-doctor`. |
| `stage_done` prints a `STORY BUDGET:` line and exits non-zero | The ceiling the project set was reached. Show the line verbatim, stop, and ask whether to finish the retro; their word continues it (`waiver.py --block "story budget"`). Nothing about the work is at fault (person-owned: money). |
