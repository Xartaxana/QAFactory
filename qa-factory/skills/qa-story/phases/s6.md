## The stand, before the first dispatch

The same check as S5's, and the same answer: read `pipeline.json`; `environment` named and
`environment_pending` false → go on; a person's word on the block `stand not confirmed`
(recorded on S5 or S6) already covers this stage — do not ask again; otherwise
`env_probe.py --env <name> --task <TICKET>`, exit 0 →
`stage_done.py --task <TICKET> --set environment_pending=false`; no name or no answer → ask
once, after the probe's lines are read as S5 does (a configured stand's name, `retry`, or `go on`; person-owned: access) and record it as S5 does, with
`--stage S6`. A stage with nothing to run asks nothing. Dispatch nothing until one holds.

The sign-in account for the screen checks is the driver's question, not yours: when it cannot find the stand's test
account it asks once, with the price of each answer — `retry` (the person puts the account where the settings point and
the driver looks again), `by hand` (the person checks those screens themselves: the cases are left with them and the
report lists them), `go on` (the cases are left unchecked, in the person's words). Each answer is carried out by the
driver. Do not ask it yourself, and do not record anything for it.

A plan whose manual-agent rows were approved at a gate A that was recorded dry has no case an agent can check by hand.
The driver asks once: `reapprove` (the test design is reviewed again, gate A is asked again, and then the cases are
checked by hand; offered only when nothing runs), `go on` (the cases stand as not checked, in the person's words) or
`stop`. A word once passed is not asked again.

A question about only SOME manual cases does not hold the rest: close S6 over the other cases (the held ones stay not checked, left unchecked), run S7, and ask the person after that, before gate B.


With a judge configured the runner is told to check a manual-agent observation against its
Then with `judge_results.py --observation --then "..." --observed "..."`, and `run_suite.py`
attaches `summary["diagnosis"]` (culprit, confidence, one sentence) to every run it makes.
The diagnosis is a reading of the log, not a verdict: `execution_status` stays what the code
derived, and a row still blocks with its own `remedy`.

Follow `references/execution-lifecycle.md`. Compare final source SHA, test/helper content,
the same execution-relevant configuration of the profile, runtime/toolchain, environment and
application-build identity with each recorded test-instance receipt.

Cases of a profile the person took over are not in your scope and not in the run report:
`stage-scope` has already dropped them, `qa-runner` never selects them, and the failure
analyst has nothing to triage for them; the manifest records them as `handed_to_person` with
what the person runs, and the factory waits for no result of them. `finalize_task.py` also
stamps every case its manifest already proves `Automated` (`status`, `automated_by`,
`red_probe`) — code writes the transition, never a role.

Take the S6 scope from the controller, never type it: `--operation stage-scope` with this
block's `execution_kind` (`manual` returns the approved `manual-agent` cases, `automation` the
automated instances). An empty scope is refused while the plan names cases for this stage.

Reuse matching fresh receipts. Code decides freshness before the runner is dispatched
(`execution_request.fresh_evidence`): when every automated test has a result on its current
bytes, on this stand and version, and no `manual-agent` case is left, it runs
`finalize_task.py` and closes S6 itself — no runner, nothing re-run. Otherwise the runner
keeps the whole automation scope and is told which results stand and which instances to run;
`--mine` answers `reused` (green) or `already_run` (red) for those that stand. Run only
automated instances whose evidence is missing or stale, plus approved `manual-agent` cases in
bounded blocks. Do not execute `manual-human` cases or impact regression. Unsupported selectors and unavailable platforms stay scoped
`unverified`/`blocked`; they never widen into a whole-suite run.
S6 reads run freshness by the one predicate (`proof_level.run_freshness`): a stale run goes to the runner, a stale live check is proved again by code (`probe_by_code`) in the close of S6 - under the open S6 dispatch when there is one, otherwise in the close context, which opens no dispatch - and the close's receipt names each probe record. With a manual half to come, the stale live checks are proved again right after the automation runner is accepted, before the first manual block (the proofs are not in a close receipt).

A rerun under the real instance ids supersedes a row the reducer could not join to a manifest
instance: the ghost stays in `results[]` marked `superseded_by_rerun`, leaves the current
projection, and stops deciding `execution_status` — so a rerun is a repair and never needs a
waiver for the attempt it replaces (TP2-2553).

A stage transition alone never makes a current result stale and never authorizes a repeat:
a result stands while the tests, the environment and the deployed version are unchanged,
and only a person's word passes a repeat. A run is due only for a recorded missing or
changed input (for example, newly detected merge-request content or deployment identity).

For each new automated run, regenerate the actual-file fingerprint, preserve exact
`instance_contracts` reporter IDs/parameters, and use the selected profile's read-only
runtime probe before and after execution. A probe timeout/change or unmatched reporter row
remains `not_run`/inconclusive. Use `run_suite.py --recover KEY --task TASK` for an interrupted
durable job; recovery does not relaunch it.

Let `finalize_task.py` reduce immutable run/manual blocks into one whole-story
`run-report.json`; do not hand-write automated rows. It includes reused, failed, skipped,
partial, blocked and not-run outcomes with evidence. It takes the task root as a positional
argument, unlike every other factory script:

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/finalize_task.py" qa-factory/artifacts/<TICKET>
```
Regression recommendations are marked not run by the factory. Record S6 and print the S7 card
(`story_step.py card --stage S7`).

Manual evidence follows `references/manual-evidence.md`; run only remaining or freshness-stale scope.
Before a manual block, code runs `manual_evidence.py prepare` per case: a refused case is not
dispatched (its `request.json` holds the reason and the door; the report says "not checked by
hand"). The runner captures with `manual_capture.py` and builds the record with
`manual_evidence.py build`; code takes the stand's runtime probe at the start and the end, and
a probe that is unmatched or failed puts the case in `env_blocked[]` with that line, no record.
A manual verdict carries a quote of the captured text per Then (`request.json` `thens`); a verdict
the runner finds wrong on its own captures is re-judged with `manual_evidence.py rejudge`, which
does not run the check again (`references/manual-evidence.md`).

Every `env_blocked[]` row carries the same `remedy` as a manifest stand gap — names only,
never a value — and names which `env_probe.py` line failed. `validate_artifacts.py` refuses
a run report that blocks with no remedy.

## Runtime first; baseline never blocks execution

The baseline machinery below stays dormant: no role captures `evidence_phase=baseline` now. The
one "before" a person is shown for a manual check is `before_change` of its record (the
register's behaviour claim, or "not recorded by the requirements"), never a capture; a
`pre_action` capture is the state before the action, not a "before the change".

Follow `references/environment-preparation.md` before any stand mutation. Inspect the
actual running revision, mounts, startup command and build inputs first. If the target
change is already running, test in place. Never switch back to main, rebuild an old version
or create another stand solely for baseline. If a suitable before state is already running,
capture useful current-case evidence there, then perform only the necessary authorized
update. Missing before evidence does not block any current test, including comparative cases.

`controller.py --task-root <TASK_ROOT> --operation deployment-inputs` reports baseline gaps;
its ready flag is not deployment authorization or a runtime health verdict. Execute current
checks and retain after evidence. Missing comparison evidence is awaiting_baseline, never a
fabricated comparison PASS and never an environment blocker for the whole case. Report
independent current assertions separately; retain real failures. Actual before captures still
use evidence_phase=baseline, exact case/version, revision, fixture, approved assertion and
hash-bound artifact receipts. Capture success is not a product verdict.

At S8 show the after results and incomplete comparisons. Ask where to obtain before evidence
(stand/revision), or whether the user will compare themselves. This follow-up does not delay
completion or retro. Production access or another deployment requires explicit authorization.
Reuse valid after evidence if before is later supplied; rerun only invalidated checks.
Recommended regression remains user-owned. See the reference for preparation job commands.
